Understand the requirement properly before building.
- Turn the request into requirements.md: Goal, Audience, Pages/Screens, Features (must / nice), Content, Style, Data and storage, Constraints, Acceptance checklist (testable items), Open questions.
- Vague request (for example "school website")? Fill sensible defaults, build a strong first version, then ask 1-2 specific questions in your reply.
- Re-read requirements.md before every edit and tick off the checklist when you finish.
